# ADR-0002：为什么采用 Plugin

- 状态：Accepted
- 日期：2026-07-29
- 决策范围：平台扩展边界

## 背景

CAP 的目标不是重写 Scrapy、Playwright、ZAP、Nuclei、Suricata、Zeek 等成熟工具，而是统一编排、治理与集成。将工具逻辑直接写入平台服务会造成技术栈绑定、升级困难和安全边界模糊。

## 决策

采用 Plugin First：

- Agent 通过独立 SDK 契约实现；
- 成熟工具通过 Tool Adapter 接口接入；
- Registry 只保存 manifest、权限、运行和资源要求；
- 编排器依赖接口、配置和策略，不按具体 Agent 或工具分支；
- 插件在后续阶段进入隔离 Runtime，平台控制面不执行工具实现细节。

## 结果

平台可以独立演进，插件可以独立发布和升级，并能统一施加权限、审批、网络策略、资源限制与审计。代价是必须维持稳定契约和兼容性测试；任何 SDK 破坏性变更都需要独立版本治理。
