## Reliability evidence (measured, not projected)

- **Whole-cluster DR:** real `kind delete cluster` destruction of Cluster A,
  fresh Cluster B, fail-closed manifest-verified restore. RPO = **9.76 s**,
  RTO = **236.75 s** (wall-clock measured, recorded in `outputs/ga-dr/`).
- **2-hour soak:** 480/480 healthy ticks, 0 HTTP errors, 0 downtime; 11
  controlled worker pod kills triggered only expected crash-recovery reclaims;
  availability 1.0; stable RSS (no long-tail memory leak in window); 480 runs
  created, 48 cancelled, 1,440 pagination requests.
- **Capacity / backpressure:** 9-cell capacity matrix (1×100 → 4×1000) with
  real executions + paginated listing; overload/backpressure gates PASS.
- **Under-load upgrade/rollback:** helm upgrade under load 7.9 s / rollback
  0.5 s, 0 HTTP errors during both.
- **Per-run lease renewal:** the acquisition run-claim lease IS renewed every
  `lease_ttl/3` on a dedicated session with fencing (see D1 resolution below).

## Security

- **CVE-2026-14456** (openssl, HIGH — unbounded QUIC memory growth DoS) fixed:
  the frontend runtime image (`nginx:1.30.4-alpine`) upgrades
  `libssl3`/`libcrypto3` `3.5.7-r0` → `3.5.8-r0` in place at build time.
- Worker never mounts a container-runtime socket (docker/containerd/cri).
  Sandbox execution goes through the Kubernetes API with namespaced RBAC to
  short-lived Pods in `cap-sandbox` (Phase 28.6 closure).
- Trivy image scans: 0 blocking HIGH/CRITICAL on release images.
- SBOM (SPDX + CycloneDX) and SLSA-style provenance generated for release
  images, tied to the final digests.

## D1 fact-conflict resolution (CLOSED)

The earlier known-limitation "per-run lease lacks renewal" was fact-checked and
found **FALSE**. The production K8s path
(`worker_main.py` → `AcquisitionWorkerLoop` → `run_claimed()` → `cancel_aware()`
→ `_renew_lease()`) renews the acquisition run-claim lease every `lease_ttl/3`
on a dedicated session with fencing-token / version-CAS stale-writer rejection.
PRE-GATE A/B/C/D all PASSED at certification. D1 is removed from known
limitations. Full proof: `outputs/cap-cert-ga/D1-FACT-CONFLICT-RESOLUTION.md`.

## Known limitations

1. **24-hour soak not yet executed.** The soak ran for 2 hours (7,200 s). A
   24-hour soak is future work for deeper confidence on long-tail memory leaks
   and run-reclaim behavior.
2. **SLO candidates are not enforced SLOs.** They are derived from a single
   2-hour soak + one DR cycle. Promotion to production SLOs requires ~30 days
   of production data and a product decision.
3. **Cancel vs. terminal-state race (Low).** A restrictive policy can finalize
   a run as BLOCKED before a cancel request lands; the cancel API is idempotent
   for already-terminal runs.
