# v1.0.0-rc4 — Security Re-Certification Anchor

**Purpose:** re-certification anchor for the v1.0.0 GA release. This RC exists
because a blocking HIGH security finding landed AFTER the original
certification anchor (`10369e7`, v1.0.0-rc3), and the fail-closed release
diff classifier correctly refuses to inherit runtime certification across a
runtime-affecting change.

## Why rc4 (and not inheriting rc3's certification)

- **CVE-2026-14456** (openssl, HIGH): unbounded memory growth in QUIC
  handling → denial of service. The frontend runtime base image
  `nginx:1.30.4-alpine` shipped openssl `3.5.7-r0`; the fixed `3.5.8-r0`
  landed in the alpine 3.24 repository on 2026-08-25, after every published
  `nginx:*-alpine` build, so no base-image tag bump could clear it.
- **Fix:** `frontend/Dockerfile` now runs
  `apk upgrade --no-cache libssl3 libcrypto3` in the runtime stage, upgrading
  the two openssl runtime libraries in place at build time. Base image stays
  `nginx:1.30.4-alpine` to minimize runtime delta.
- **Classification:** the added `RUN` line is a deployment change, so
  `scripts/release/classify_diff.py` (fail-closed) marks any diff containing
  it `runtime_affecting=true`. Certification therefore CANNOT be inherited
  from `10369e7` — it must be re-earned on a commit that already contains the
  fix. That commit is this anchor.
- Also carried in this anchor: the ruff F401 fix in
  `backend/tests/test_release_version_consistency.py` (unused `import pytest`)
  that blocked the release workflow's quality-gates job.

## Certification plan

- Full Phase 28.7 GA certification (40 gates, `CAP_GA_STRICT=1`) runs on THIS
  commit via the GA Certification + GA Reliability (soak) workflows, with the
  Linux Certification suite re-certifying the same SHA (GA-GATE 33).
- The eventual `1.0.0` GA commit will be a PURE release-metadata bump from
  this anchor (version carriers only + `artifacthub.io/prerelease` flip),
  which the classifier judges `release_metadata_only=true` → certification
  INHERITED.

## Version alignment

Version aligned to `1.0.0-rc4` across VERSION, backend pyproject/uv.lock
(PEP 440 `1.0.0rc4`), frontend package.json/package-lock, sdk, Helm chart
(version/appVersion/image tags), Dockerfile `ARG VERSION`, and the
runtime-reported `app_version` / `__version__`. Enforced by
`backend/tests/test_release_version_consistency.py`.

See `CHANGELOG.md` and the Phase 28.7 GA certification artifacts
