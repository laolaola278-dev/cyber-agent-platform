## Release-process finding (recorded for future anchors)

The first strict GA dispatch on this line was blocked by GA-GATE 33: the
same-SHA Linux certification run `33946618296` had failed two SQLite-backed
28.2 tests under CI load:

- `test_claim_loop_executes_end_to_end` — `RUNNING != COMPLETE`
- `test_execution_flows_through_sandbox_boundary` —
  `sqlite3.OperationalError: cannot commit transaction - SQL statements in progress`

Triage (recorded in `docs/quality/cert-rerun-triage-33946618296.md`):
backend code is byte-identical between the last success and this failure
(only version metadata changed in `9dbe60f..87d2409`); 12+ consecutive
successes since 2026-08-31 make this the first failure; both tests share a
single async session between the test body and the execution path, which is
a load-sensitive SQLite-only hazard (production runs PostgreSQL). Classified
**harness race, non-product**. The certification was re-run on the same SHA
and the evidence chain was repaired that way (no code change, no soak
invalidation).
