# v1.0.3-rc1 — Frontend Console Refactor Release Candidate

> **Release candidate for v1.0.3.** This is the first RC of the 1.0.3 line and
> exists for one reason: the console refactor below touches files under
> `frontend/src/**`, which `scripts/release/classify_diff.py` classifies as
> `production_runtime`:
>
> ```
> python scripts/release/classify_diff.py 9aad312 6a16799
>   -> 9 files  category=production_runtime  runtime_affecting=true
>   -> RESULT: RECERTIFICATION REQUIRED
> ```
>
> The v1.0.2 GA certification therefore **cannot be inherited**. The refactor
> must earn its own certification at this anchor; a subsequent pure
> version-metadata commit will promote `1.0.3-rc1` → `1.0.3` (verdict
> `INHERITED`).

**Anchor:** `9aad312` (v1.0.2 promote) → `6a16799` (this RC HEAD).

### Frontend structure

`App.tsx` was a single ~1500-line file holding every console view. It is now a
**shell + navigation**, with nine views extracted verbatim into `pages/`:

`IncidentsPage` · `AssetsPage` · `AssessmentPage` · `DetectionPage` ·
`ResponsePage` · `PlaybooksPage` · `KnowledgePage` · `WorkersPage` ·
`AuditPage`

The remaining views (`dashboard`, `plugins`, `approvals`, `investigations`,
`access`, `settings`, acquisition) stay inline in `App.tsx` — extracted pages
are rendered by the existing `activeKey` state switch, **not** a router, so
navigation semantics are unchanged.

Three new shared layers:

- `api/http.ts` — one `axios` instance (`baseURL` from
  `VITE_API_BASE_URL`, default `/api`; 10 s timeout; `withCredentials`) plus an
  `errorMessage()` helper that surfaces the backend's `detail` field.
- `api/constants.tsx` — status/severity tag rendering and `formatTime`.
- `hooks/usePageList.ts` — server-side pagination list hook.
- `types.ts` — **+370 lines** of typed API models. `Finding` gained
  `created_at` / `updated_at` to match the backend `FindingRead` schema.

### What did **not** change

This is a presentation-layer refactor. There is **no** change to:

- `backend/**` (no API, service, schema, or migration change)
- `deployment/**` (no Helm, image, or topology change)
- database schema or migrations
- Python/JS dependency sets

The HTTP surface the console calls is byte-for-byte the same set of
`api/client.ts` functions as before the refactor.

## Why recertification is still required

The classifier is **path-based and fail-closed**: any file under
`frontend/src/` is `production_runtime` unless the content-aware check proves
the diff is a pure version-bump. That is the correct default — a content-agnostic
exemption for "frontend only" would let a real logic change slip through under a
cosmetic label.

So: the change carries **low runtime risk** (browser bundle only, no server
logic touched) but it is **not certification-exempt**. The v1.0.2 GA evidence
covers a console bundle that no longer exists; re-running the 40 gates is what
establishes that the rebuilt bundle still deploys, serves, and behaves under
the same soak and capacity profile.

## Known limitations

Carried forward from v1.0.2 — unchanged by this RC:

- **Response EDR/WAF/Firewall providers remain mock-only.** No production
  device integration exists in the tree.
- **Zeek TSV is unsupported.** JSONL is the only supported ingest format.
- **24-hour soak not executed.** The certified soak for this line ran 2 hours
  (480/480 ticks, 0 errors, availability 1.0).
- **SLOs remain candidates**, pending a full month of production data.

The egress-proxy CONNECT defect fixed in v1.0.2 stays fixed; its regression
tests (`tests/test_phase_28_5_egress_proxy.py`) remain in `ci.yml`.
