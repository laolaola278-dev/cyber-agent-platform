## Frontend console refactor

`App.tsx` had grown into a single ~1500-line file holding every console view.
It is now a **shell + navigation**, with nine views extracted verbatim into
`pages/`:

`IncidentsPage` · `AssetsPage` · `AssessmentPage` · `DetectionPage` ·
`ResponsePage` · `PlaybooksPage` · `KnowledgePage` · `WorkersPage` ·
`AuditPage`

The remaining views (`dashboard`, `plugins`, `approvals`, `investigations`,
`access`, `settings`, acquisition) stay inline in `App.tsx`. Extracted pages
are rendered by the existing `activeKey` state switch — **not** a router — so
navigation semantics are unchanged.

Three new shared layers replace copy-pasted logic:

- `api/http.ts` — one `axios` instance (`baseURL` from `VITE_API_BASE_URL`,
  default `/api`; 10 s timeout; `withCredentials`) plus an `errorMessage()`
  helper that surfaces the backend's `detail` field.
- `api/constants.tsx` — status/severity tag rendering and `formatTime`.
- `hooks/usePageList.ts` — server-side pagination list hook.
- `types.ts` — typed API models (+370 lines). `Finding` gained
  `created_at` / `updated_at` to match the backend `FindingRead` schema.

The HTTP surface the console calls is the same set of `api/client.ts`
functions as before the refactor.

### CI gaps found and fixed during this release

Three defects surfaced while wiring the FULL GA proof end-to-end in CI. All
were **harness/certification-infrastructure** defects — no product code change
is involved.

1. **Reliability gates structurally unreachable from CI** (`2e4d0b1`). The
   push-triggered GA workflow always reported
   `IMPLEMENTED-SCOPE PASS / FULL GA NOT CERTIFIED` because the step that
   merges reliability evidence used `actions/download-artifact@v4`
   **without `run-id` or `github-token`**. That action is same-run only, and
   `cap-ga-reliability.yml` has no `workflow_call` trigger, so gates
   24/25/26/34/35 were always `PLANNED`. The GA workflow now resolves the
   soak run **for the current commit** via the API and downloads its artifact
   with `run-id` + `github-token`; a `workflow_dispatch` input `ga_strict`
   switches `CAP_GA_STRICT=1` for full-GA dispatches (push/PR runs stay in
   development mode, since a 2-hour soak per push is not viable).
   Note on the API: the workflow-runs endpoint **ignores** a `conclusion`
   query parameter (an in-progress run is returned even with
   `conclusion=success`), so the workflow filters with `status=completed`
   server-side and selects the successful run in jq. A soak that is still
   running — or that failed — yields no evidence, which is the correct
   fail-closed behaviour.
2. **Heartbeat ARCH INVARIANT suite was never executed by any workflow**
   (`2e4d0b1`, fixture fix `4bc5169`). The suite pinning the `2ba8bec`
   production fix — execution-lease renewal must never share the runtime
   `AsyncSession`, or a dying heartbeat lets a HEALTHY run be falsely
   reclaimed — existed in the tree but was referenced by no pipeline, so the
   report's `heartbeat_invariant` block was permanently `NOT_RUN` while
   `full_ga_certified` still read true. The suite is now part of the GA
   certification pytest list, and its CI debut immediately caught two real
   fixture defects (next item).
3. **Heartbeat fixture DB semantic mismatch + report fidelity**
   (`2e4d0b1` + `4bc5169`). The three behavioral heartbeat tests acquired
   leases for bare `uuid4()` ids without registering the worker first;
   SQLite does not enforce FKs by default, so both SQLite variants passed
   silently while PostgreSQL (authoritative) correctly rejected them with
   `fk_worker_leases_worker_id_workers` — a textbook SQLite-lax / PG-strict
   mismatch, fixed at the fixture via `WorkerRegistry.register`. The PG test
   also now cleans up in `finally`: a mid-test failure used to leak the
   checked-out asyncpg connection, whose GC finalizer fired minutes later
   and pytest's unraisable hook attributed the SAWarning to whichever long
   test was running (that is how the fixture bug poisoned the 27-minute
   capacity gate in the first wired run). Report generator fidelity fixes
   shipped alongside: `_section()` now accepts non-empty list sections
   (`images.json` stores the digest roll-up as a LIST and was silently
   discarded as `NOT_EXECUTED`), and the `security` section reads
   `security-recert.json` (the file the workflow actually writes) honouring
   it only when `head_sha` matches the current commit.

## Known limitations

Carried forward from v1.0.2, unchanged:

- **Response EDR/WAF/Firewall providers remain mock-only.** No production
  device integration exists in the tree.
- **Zeek TSV is unsupported.** JSONL is the only supported ingest format.
- **24-hour soak not executed.** The certified soak for this line ran 2 hours.
- **SLOs remain candidates**, pending a full month of production data.
