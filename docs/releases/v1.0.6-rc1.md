# v1.0.6-rc1 — Post-1.0.5 Delivery Audit Anchor

> **RC anchor for the 1.0.6 development line.** v1.0.5 is published and
> immutable (`v1.0.5` -> `32ec298`, GitHub Release "Cyber Agent Platform v1.0.5",
> 2026-09-07), so the post-release work below cannot ship as 1.0.5; the version
> policy requires a new RC. This commit is a pure version-metadata bump over the
> audited tree, so the audited content and the anchor are the same runtime.
>
> `python scripts/release/classify_diff.py 32ec298 <pre-anchor>` reports
> `64 files, runtime_affecting=true, RECERTIFICATION_REQUIRED`
> (production_runtime 48 | test_harness 6 | docs 5 | dependency 2 |
> ci_workflow 1 | database 1 | deployment 1). The v1.0.5 certification is
> therefore **not inherited** — this anchor re-certifies.

## What is on this line

Runtime-affecting:

- **Asset search 500 on PostgreSQL** (`41bbc49`) — `AssetRepository.search`
  applied `statement.distinct()` unconditionally, so its count query became
  `SELECT DISTINCT` over every asset column and PostgreSQL has no equality
  operator for the `json` columns. `GET /assets` answered 500; SQLite accepted
  both shapes, which is why 1200 unit tests never saw it. The tag filter is now
  an id semi-join and the `DISTINCT` is gone.
- **`CAP_ZAP_API_KEY` was documented but never consumed** (`41bbc49`) —
  `Settings` had no matching field and `model_config` uses `extra="ignore"`, so
  `MemorySecretProvider` could never hold the `zap-api-key` reference
  `get_zap_api_key` resolves. Every route reaching `AssessmentService` failed
  with `SECRET_NOT_FOUND`, and because `POST /incidents` depends on
  `PlaybookService` -> `AssessmentService`, **creating an incident was
  impossible on a fresh deployment**.
- **Audit attribution** (`41bbc49`) — API-path audit events and
  `Asset.deleted_by` recorded the literal `api-user` instead of the
  authenticated principal.
- **Workflow approval gate** (`89eac38`) — `ApprovalNodeHandler` was the Phase 3
  placeholder that always returned `WAITING`, so a playbook with a human gate
  could be started and never finished, and `POST /workflow/run/{id}/resume` just
  parked it again. A reviewer decision recorded through
  `POST /workflow/run/{instance_id}/decision` now opens (`APPROVED`) or
  terminates (`REJECTED`, with the reviewer's reason) the run; the decision is
  persisted on the run context and a gate cannot be answered twice.
- **Authorization mapping** (`89eac38`) — that route resolves to
  `approval.decide`, the permission that already governs response-plan
  approvals, instead of falling through to `platform.manage`.
- **Error text shown to operators** (`89d494c`) — the console read only
  FastAPI's `detail` string, so every platform-envelope failure showed axios's
  own status text and every validation failure showed `[object Object]`.
  `errorMessage()` now reads all three shapes.
- **Console completeness** (`5eeb1b8`, `b2c12c5`, `89d494c`, `8812381`,
  `7a738fc`) — real loading/error/empty states on the shell-owned views, the
  acquisition resume/cancel lifecycle wired, the Approval Center and Plugin
  inventory completed, five unnamed action columns labelled, the Playbook
  document card relabelled to the JSON it renders, and the incident assignment
  dialog no longer fires a request that changes no field.
- **Version carrier that lied** (`1a55df0`) — `docker-compose.yml` defaulted
  `APP_VERSION` to a literal five releases old, and the console now displays
  `/health`'s version, so a compose deployment self-reported the wrong release.
- **Certification gate portability** (this line) —
  `scripts/release/classify_diff.py` decoded git output with the platform
  encoding; on a GBK Windows console any non-ASCII byte in a diff killed the
  reader thread and the gate died with an unrelated `AttributeError`. It now
  decodes UTF-8 explicitly and fails loudly rather than reporting "no changed
  lines".

Schema: **no `backend/alembic/versions` file differs from v1.0.5** — the
migrated schema is unchanged, so PostgreSQL migration evidence from the v1.0.5
line applies to the schema itself, while the runtime that reads it must still be
re-certified at this anchor.

## What this anchor must still earn before a release decision

The local run cannot certify container, Redis, MinIO, OCI sandbox, nginx or
Kubernetes behaviour (this workstation has no Docker/WSL), so at this anchor:

1. CI on the candidate SHA (lint/typecheck/tests/coverage/Alembic head).
2. CAP Linux Certification with critical skips = 0.
3. K8s Certification (kind + CNI + NetworkPolicy + sandbox provider, worker with
   no runtime socket, egress control, pod-kill recovery).
4. Container image builds recorded by digest + SBOM + provenance + Trivy policy.
5. Redis and MinIO paths against real services; nginx/frontend routing on the
   release image; Helm install and upgrade against released data.
6. GA gates classified explicitly into inherited vs re-run, with reasons, rather
   than re-run blindly or inherited silently.
