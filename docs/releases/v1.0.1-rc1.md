## Security hardening

- **Production sandbox admission is fail-closed.** A sandbox provider is
  admitted on declared capabilities, not on its name. A production deployment
  whose provider cannot prove real isolation is refused at startup instead of
  quietly starting a weaker one.
- **Production egress enforcement is required.** With enforcement missing or
  unreachable, the worker stops claiming network work — it never falls back to
  a direct egress path. Pod-level isolation is unchanged and independently
  proven: with the egress proxy scaled to zero, an isolated sandbox pod gets
  `Connection refused`.
- **Unknown providers no longer silently fall back.** Through v1.0.0 an
  unrecognised `SANDBOX_PROVIDER` — including a typo such as
  `kubernettes-sandbox` — silently started the zero-isolation memory provider.
  Unknown names now fail closed in every environment.
- **Response Plane mock-only disclosure.** The mock-only status of the EDR,
  WAF and firewall policies is disclosed by the capability surface and enforced
  by the policy models, so an operator cannot mistake simulation for device
  integration.
- **Zeek JSONL-only disclosure.** The ingest contract is stated explicitly, and
  a TSV input now fails with an actionable message naming the supported format
  and the remediation (`LogAscii::use_json=T`) instead of a generic parse error.

## Breaking operational behavior

**Raw or custom production deployments must now explicitly satisfy the sandbox
and egress requirements.** Deployments that relied on an unset
`SANDBOX_PROVIDER` (previously defaulting to a subprocess sandbox with no
network, filesystem or resource boundary) or on an empty `EGRESS_PROXY_URL`
(previously logging one line and egressing directly) will be **refused at
startup** in production. Development and testing are unaffected: a weak
sandbox is still allowed there, with an explicit warning.

Read [`docs/deployment/upgrade.md`](../deployment/upgrade.md) before upgrading
— it contains the configuration changes required for the worker to start.

## Known limitations

These are **pre-existing, disclosed limitations carried forward** — not
regressions introduced by this release:

- **Response EDR/WAF/Firewall providers remain mock-only.** No production
  device integration exists in the tree; enabling one is not a configuration
  option. The approval, evidence, audit and rollback framework around them is
  real and certified.
- **Zeek TSV is unsupported.** JSONL is the only supported ingest format; TSV
  input is rejected with an actionable error.
- **24-hour soak not executed.** The certified soak for this release ran for
  2 hours. The 24-hour endurance run remains outstanding.
- **SLOs remain candidates.** The SLO values are derived from measured data as
  candidates; promotion to enforced SLOs is a product decision after a full
  month of production data.
