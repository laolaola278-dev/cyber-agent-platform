# v1.0.5-rc1 — Race Hardening & Real-Probe RC

> **RC anchor for the 1.0.5 development line.** The code at this anchor
> versus the v1.0.4 release (`dbd33ed`) is seven commits:
>
> - **Worker lease-heartbeat race fix** (`0708012`) — cooperative teardown: a
>   stop event plus interruptible wait replaces the bare
>   ``heartbeat_task.cancel()`` in ``WorkerRuntime.execute``'s finally. The
>   old cancel could land while a TTL renewal UPDATE was in flight; the
>   abandoned statement held the SQLite write lock in a zombie transaction
>   until CPython GC finalised it, observed as a 22-33s "database is locked"
>   stall in the release UPDATE (product race — full triage in
>   `docs/quality/flake-triage-34012500372-pregate-d.md`). With the fix the
>   resonant renewal never starts and release latency drops 22.27s -> ~62ms.
> - **CI governance** (`f82b8cb`) — `scripts/quality/assert_coverage_matrix.py`
>   stdlib-only assertion + backend job fail-fast; every ❌ cell in the
>   coverage matrix must carry an accountability anchor.
> - **Frontend route-level code splitting** (`3ad23e5`) — 15 pages via
>   `React.lazy`, antd manualChunks pin removed; the 1213 kB monolith is
>   eliminated and first-paint gzip drops 437 -> 243 kB (-44%).
> - **Real outbound probes** (`aa3774e`) — notification webhook/ticket tests
>   now exercise a real HTTP round trip against a local asyncio acceptance
>   server (httpx), clearing two ❌ cells in the coverage matrix.
> - **libuuid CVE remediation** (`000dee1`) — `frontend/Dockerfile` gains
>   `apk upgrade --no-cache libuuid`, clearing 7 HIGH CVEs from the
>   util-linux base-layer drift (53612/53613/53614/76642/78408/78409/78410).
> - **Worker-path test isolation** (`b0a0d76`) — per-test file-backed SQLite
>   (NullPool+WAL+timeout) for 28.2 worker-path/claim-loop suites; the shared
>   StaticPool single connection could be interleaved by a worker path
>   opening its own poll session (SQLite-only hazard).
> - **Assertion-semantics audit** (`53b9400`, docs-only) — P1 audit, zero
>   defect-as-assertion findings, report in
>   `docs/quality/assertion-semantics-audit.md`.
>
> `scripts/release/classify_diff.py 87d2409 abed26f` classifies
> `backend/app/worker/runtime.py`, `frontend/src/**`, the frontend Dockerfile
> and the governance script as `production_runtime` (fail-closed by design), so
> the v1.0.4 certification is NOT inherited — this rc re-certifies from
> scratch.
